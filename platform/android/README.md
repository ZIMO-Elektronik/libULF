# Android

This library can be used on Android by utilizing JNI and a fitting java binding. 

## Usage

> [!NOTE]
> After the API change, the JNI remains largely untested. Definition mismatch between jni and adapter may still lead to runtime errors.

> [!NOTE]
> Android is more restrictive regarding USB usage permissions. It is currently impossible to request USB permissions from the native side. As such, a USB connection must be created from Java and the fileDescriptor can then be used by this library. 

In theory, only the `settings.gradle.kts` and `build.gradle.kts` need to be extended (this should work with groovy as well)

For `settings.gradle.kts`, the following lines need to be added
```
include(":ulf")
project(":ulf").projectDir = file("libulf/platform/android")
```

For `build.gradle.kts`, the dependency is added as follows
```
dependencies {
### ... Your other dependencies ...
    implementation(project(":ulf"))
### ... Some more other dependencies ...
}
```

This should allow the project to instanciate the `at.zimo.ulf.ULF` class (and its respective sub and helper classes) and use it. The platform specific binaries are generated by gradle.

This library expects a `cmake` version >= 3.25.0. If no version is specified, the newest version located in `ANDROID_SDK_ROOT` is used automatically. However, it is possible to explicitly specify a version using e.g. `local.properties` 

The Library will evaluate properties (and variables) in the following order

| Step | Evaluated         | CMake Version   | NDK Version   | SDK Dir            |
| :--- | ----------------- | --------------- | ------------- | ------------------ |
| 1.   | gradle.properties | `cmake.version` | `ndk.version` | `sdk.dir`          |
| 2.   | rootProject.extra | `cmakeVersion`  | `ndkVersion`  | `sdkDir`           |
| 3.   | project.extra     | `cmakeVersion`  | `ndkVersion`  | `sdkDir`           |
| 4.   | env Variables     | `CMAKE_VERSION` | `NDK_VERSION` | `ANDROID_SDK_HOME` |
| 5.   | local.properties  | `cmake.version` | `ndk.version` | `sdk.dir`          |

If none of the above are set, the newest version available in the sdk home will be used.
